# Fanticon 6502 Programmer's Reference

This manual is for developers writing 6502 machine code that runs inside the
Fanticon virtual machine. It describes the NMOS MOS 6502 instruction set,
observable CPU behavior, and cycle costs. It does not describe the Rust API used
to embed the CPU.

Fanticon's machine memory map, graphics, audio, input, cartridge format, and
system-call conventions will be documented separately as those parts of the
console are defined. Until then, addresses used in examples are illustrative.

## Quick reference

The 6502 is an 8-bit, little-endian processor with a 16-bit address space. It can
address 65,536 bytes from `$0000` through `$FFFF`.

| Register | Width | Purpose |
| --- | ---: | --- |
| `A` | 8 bits | Accumulator; arithmetic, logic, and most data operations |
| `X` | 8 bits | Index register; indexed addressing, counters, and stack-pointer transfers |
| `Y` | 8 bits | Index register; indexed addressing and counters |
| `SP` | 8 bits | Stack pointer; the physical stack address is `$0100 + SP` |
| `PC` | 16 bits | Address of the next instruction byte |
| `P` | 8 bits | Processor status flags, written as `NV-BDIZC` |

All arithmetic wraps. Incrementing `$FF` produces `$00`; decrementing `$00`
produces `$FF`; and a 16-bit address increment from `$FFFF` wraps to `$0000`.

Unless stated otherwise, examples use conventional 6502 assembly syntax:

```asm
label:  lda #$2a       ; immediate value $2A
        sta $0200      ; write it to memory
        inx            ; X = X + 1
        bne label      ; branch while X is nonzero
```

Assembler directives, label syntax, and number prefixes can vary. `$2A` means
hexadecimal, `%00101010` means binary, and `42` means decimal in this document.

## Status flags

The status register is conventionally displayed as `NV-BDIZC`, from bit 7 to
bit 0.

| Bit | Name | Meaning when set |
| ---: | --- | --- |
| 7 | `N` — Negative | The result's bit 7 is `1` |
| 6 | `V` — Overflow | Signed arithmetic overflow occurred |
| 5 | `-` — Unused | Reads as/set in stacked status; do not use as program state |
| 4 | `B` — Break | Marker present in status pushed by `BRK`/`PHP`; not a physical stored flag |
| 3 | `D` — Decimal | `ADC` and `SBC` use BCD adjustment |
| 2 | `I` — Interrupt disable | Maskable IRQ recognition is disabled |
| 1 | `Z` — Zero | The result was zero |
| 0 | `C` — Carry | Carry, no-borrow, or shifted-out bit, depending on the instruction |

`N` is a copy of result bit 7 and does not by itself mean that an unsigned value
is invalid. `V` is specifically useful for signed arithmetic. For addition,
signed overflow occurs when two operands with the same sign produce a result
with the opposite sign.

For subtraction and comparison, `C=1` means **no borrow**. After `CMP value`, for
example, `C=1` means `A >= value` in an unsigned comparison.

The `B` bit needs special care: it is not a persistent latch inside a real NMOS
6502. `BRK` and `PHP` push it as `1`; hardware IRQ and NMI push it as `0`.

## Memory and byte order

The processor stores 16-bit values in little-endian order: the low byte is at
the lower address.

```text
Value $1234 stored at $2000:
  $2000 = $34
  $2001 = $12
```

Important CPU-owned regions and vectors are:

| Address | Purpose |
| --- | --- |
| `$0000-$00FF` | Zero page; shorter and usually faster addressing |
| `$0100-$01FF` | Hardware stack page |
| `$FFFA-$FFFB` | NMI vector, low byte then high byte |
| `$FFFC-$FFFD` | RESET vector, low byte then high byte |
| `$FFFE-$FFFF` | IRQ/BRK vector, low byte then high byte |

These are CPU conventions, not a complete Fanticon memory map.

### Reset entry

Reset takes seven CPU cycles, sets `I`, and loads `PC` from `$FFFC/$FFFD`. It does
not give application code useful initial values in `A`, `X`, or `Y`, and NMOS
reset does not clear decimal mode. A reset entry point should establish every
machine-state assumption it needs:

```asm
reset:
        sei             ; mask IRQ while initializing
        cld             ; use binary arithmetic
        ldx #$ff
        txs             ; begin with a known stack position

        ; Initialize RAM and Fanticon devices here.
        ; Enable interrupts only after their handlers and sources are ready.
        cli
main:
        jmp main
```

The exact initial stack value is not an application interface. Setting `SP`
explicitly also makes soft-restart behavior predictable.

## Addressing modes

`M` below means the byte at the effective memory address. `P` in the cycle column
means “add one cycle if indexing crosses a 256-byte page.” A page boundary is
crossed when the high byte of the effective address differs from the unindexed
base address.

| Mode | Example | Bytes | Effective operand |
| --- | --- | ---: | --- |
| Implied | `clc` | 1 | Operation has no explicit operand |
| Accumulator | `asl a` | 1 | Operates on `A` |
| Immediate | `lda #$40` | 2 | The byte following the opcode |
| Zero page | `lda $40` | 2 | Address `$0040` |
| Zero page,X | `lda $40,x` | 2 | `($40 + X) & $FF` |
| Zero page,Y | `ldx $40,y` | 2 | `($40 + Y) & $FF` |
| Absolute | `lda $2040` | 3 | Address `$2040` |
| Absolute,X | `lda $2040,x` | 3 | `$2040 + X` |
| Absolute,Y | `lda $2040,y` | 3 | `$2040 + Y` |
| Relative | `bne label` | 2 | Signed 8-bit displacement from the PC after the branch |
| Indexed indirect | `lda ($40,x)` | 2 | Read a 16-bit pointer from zero page at `($40 + X) & $FF` |
| Indirect indexed | `lda ($40),y` | 2 | Read a zero-page 16-bit pointer, then add `Y` |
| Absolute indirect | `jmp ($2040)` | 3 | Read the jump destination pointer at `$2040` |

Zero-page indexing always wraps within zero page. If `X=$30`, `$F0,x` addresses
`$0020`, not `$0120`. Zero-page pointer reads wrap similarly: a pointer beginning
at `$FF` gets its low byte from `$00FF` and high byte from `$0000`.

The original NMOS 6502 also has the indirect `JMP` page-wrap behavior. If the
pointer operand is `$12FF`, `JMP ($12FF)` reads its destination low byte from
`$12FF` and its high byte from `$1200`, not `$1300`. Code can rely on Fanticon
matching this behavior, though placing an indirect-jump pointer across a page is
usually best avoided.

## Instruction notation and timing

The tables use these abbreviations:

| Abbreviation | Meaning |
| --- | --- |
| `A`, `X`, `Y`, `SP`, `PC`, `P` | CPU registers |
| `M` | Memory operand |
| `#` | Immediate operand |
| `C`, `Z`, `I`, `D`, `V`, `N` | Status flags |
| `←` | Assignment |
| `&`, `|`, `^` | Bitwise AND, OR, exclusive OR |
| `~` | Bitwise complement |
| `P` after a cycle count | Add 1 cycle on a page crossing |

Cycle counts include opcode fetch and are exact for normal execution. Branches
take 2 cycles when not taken, 3 when taken on the same page, and 4 when taken
across a page. Read instructions with absolute indexed or indirect indexed modes
often have a conditional page-crossing cycle. Stores and read-modify-write
instructions instead have fixed timing and still perform their required dummy
bus accesses.

## Load, store, and transfer instructions

| Instruction | Operation | Flags |
| --- | --- | --- |
| `LDA` | `A ← M` | `N Z` |
| `LDX` | `X ← M` | `N Z` |
| `LDY` | `Y ← M` | `N Z` |
| `STA` | `M ← A` | None |
| `STX` | `M ← X` | None |
| `STY` | `M ← Y` | None |
| `TAX` | `X ← A` | `N Z` |
| `TAY` | `Y ← A` | `N Z` |
| `TXA` | `A ← X` | `N Z` |
| `TYA` | `A ← Y` | `N Z` |
| `TSX` | `X ← SP` | `N Z` |
| `TXS` | `SP ← X` | None |

`TXS` deliberately does not update `N` or `Z`.

## Arithmetic and comparison

| Instruction | Operation | Flags |
| --- | --- | --- |
| `ADC` | `A ← A + M + C` | `N V Z C` |
| `SBC` | `A ← A - M - (1-C)` | `N V Z C` |
| `CMP` | Compute `A - M`, discard result | `N Z C` |
| `CPX` | Compute `X - M`, discard result | `N Z C` |
| `CPY` | Compute `Y - M`, discard result | `N Z C` |
| `INC` | `M ← M + 1` | `N Z` |
| `DEC` | `M ← M - 1` | `N Z` |
| `INX` | `X ← X + 1` | `N Z` |
| `INY` | `Y ← Y + 1` | `N Z` |
| `DEX` | `X ← X - 1` | `N Z` |
| `DEY` | `Y ← Y - 1` | `N Z` |

Set or clear carry before multi-byte addition and subtraction:

```asm
; [$11:$10] = [$11:$10] + [$21:$20]
        clc
        lda $10
        adc $20
        sta $10
        lda $11
        adc $21
        sta $11

; [$11:$10] = [$11:$10] - [$21:$20]
        sec
        lda $10
        sbc $20
        sta $10
        lda $11
        sbc $21
        sta $11
```

For unsigned comparisons, use `BCC` for less-than and `BCS` for greater-than or
equal after `CMP`, `CPX`, or `CPY`. Equality uses `BEQ`/`BNE`. Signed comparisons
need logic combining `N` and `V`; the 6502 has no direct signed branch.

## Logic, bit test, and shifts

| Instruction | Operation | Flags |
| --- | --- | --- |
| `AND` | `A ← A & M` | `N Z` |
| `ORA` | `A ← A | M` | `N Z` |
| `EOR` | `A ← A ^ M` | `N Z` |
| `BIT` | Test `A & M`; copy `M` bits 7 and 6 to `N` and `V` | `N V Z` |
| `ASL` | Shift left; bit 7 goes to `C`, bit 0 becomes 0 | `N Z C` |
| `LSR` | Shift right; bit 0 goes to `C`, bit 7 becomes 0 | `N Z C` |
| `ROL` | Shift left through carry | `N Z C` |
| `ROR` | Shift right through carry | `N Z C` |

Shifts operate either on `A` or on memory. `ASL` is multiplication by two when
overflow is intentionally ignored; `LSR` is unsigned division by two. Rotates
are useful for multi-byte shifts because carry connects adjacent bytes.

```asm
; Shift the 16-bit value at [$11:$10] left once.
        asl $10
        rol $11
```

`BIT` does not change `A`. It is useful both for testing a mask and for reading
flag-like bits 7 and 6 from a hardware register.

## Branches, jumps, and subroutines

| Instruction | Condition or operation | Base cycles |
| --- | --- | ---: |
| `BCC` | Branch if `C=0` | 2 + taken + page |
| `BCS` | Branch if `C=1` | 2 + taken + page |
| `BEQ` | Branch if `Z=1` | 2 + taken + page |
| `BNE` | Branch if `Z=0` | 2 + taken + page |
| `BMI` | Branch if `N=1` | 2 + taken + page |
| `BPL` | Branch if `N=0` | 2 + taken + page |
| `BVC` | Branch if `V=0` | 2 + taken + page |
| `BVS` | Branch if `V=1` | 2 + taken + page |
| `JMP abs` | `PC ← address` | 3 |
| `JMP (abs)` | `PC ← pointer value` | 5 |
| `JSR abs` | Push return address, then jump | 6 |
| `RTS` | Pull return address, add one, then return | 6 |
| `RTI` | Pull status and PC | 6 |

A relative branch can reach from 128 bytes backward to 127 bytes forward from
the address immediately after its operand. Assemblers normally diagnose a target
that is out of range. A common long conditional branch inverts the condition and
jumps:

```asm
        beq nearby       ; original intent: BNE far_away
        jmp far_away
nearby:
```

`JSR` pushes the address of the last byte of its own instruction. `RTS` pulls
that value and adds one. Treat the representation as an implementation detail;
pair `JSR` with `RTS` and do not try to return with `RTI`.

## Stack and interrupt instructions

The stack occupies `$0100-$01FF`. A push writes to `$0100 + SP` and then
decrements `SP`. A pull increments `SP` and then reads from `$0100 + SP`. Stack
overflow and underflow are not trapped; `SP` simply wraps within page 1.

| Instruction | Operation | Cycles | Flags changed |
| --- | --- | ---: | --- |
| `PHA` | Push `A` | 3 | None |
| `PHP` | Push status with `B=1`, unused bit set | 3 | None |
| `PLA` | Pull `A` | 4 | `N Z` |
| `PLP` | Pull status | 4 | Status restored |
| `BRK` | Software interrupt through `$FFFE/$FFFF` | 7 | `I` set |
| `RTI` | Pull status, then PC | 6 | Status restored |

`BRK` is a two-byte operation in practice. The CPU increments `PC` past the byte
following the opcode before stacking it, so debuggers and inline data schemes
must account for the padding/signature byte.

On IRQ or NMI, the CPU pushes PC high, PC low, and status, sets `I`, then reads
the vector. IRQ uses `$FFFE/$FFFF`; NMI uses `$FFFA/$FFFB`. `RTI` restores the
interrupted status and exact return address.

Interrupt handlers must preserve any registers they modify:

```asm
irq_handler:
        pha
        txa
        pha
        tya
        pha

        ; Acknowledge the interrupt source and do time-critical work here.

        pla
        tay
        pla
        tax
        pla
        rti
```

This sequence preserves `A`, `X`, and `Y`. `RTI` restores the original flags, so
the temporary `PLA`/transfer flag changes do not escape the handler.

## Flag-control and miscellaneous instructions

| Instruction | Effect | Cycles |
| --- | --- | ---: |
| `CLC` | `C ← 0` | 2 |
| `SEC` | `C ← 1` | 2 |
| `CLI` | `I ← 0` | 2 |
| `SEI` | `I ← 1` | 2 |
| `CLD` | `D ← 0` | 2 |
| `SED` | `D ← 1` | 2 |
| `CLV` | `V ← 0` | 2 |
| `NOP` | No register or memory result | 2 |

The NMOS interrupt-polling behavior around `CLI` and `SEI` is cycle-specific. An
IRQ already asserted during `CLI` is normally recognized after one more
instruction; an IRQ observed around `SEI` can still be taken based on the old
`I` value. Avoid depending on the edge case unless writing timing-sensitive low
level code.

## Decimal mode

With `D=1`, `ADC` and `SBC` perform the NMOS 6502's binary-coded-decimal (BCD)
adjustment. Each nibble represents a decimal digit, so `$42` represents decimal
42. Decimal mode does not affect increment, decrement, comparison, or shifts.

```asm
        sed
        clc
        lda #$45
        adc #$38        ; A becomes $83
        cld             ; return to binary arithmetic
```

Fanticon implements NMOS decimal behavior, including inputs that are not valid
BCD digits. `N`, `V`, and `Z` in decimal operations have NMOS-specific behavior
and should not be treated as portable BCD result indicators. Prefer `C` for the
decimal carry/no-borrow and explicitly test `A` when necessary.

Interrupt entry on an NMOS 6502 does not clear `D`. An interrupt handler that
uses arithmetic should use `CLD` or preserve its assumptions. Application code
should generally leave decimal mode clear except inside a small, controlled BCD
routine.

## Cycle-accurate programming rules

Fanticon exposes real NMOS bus timing, including accesses whose values a simple
instruction emulator might ignore:

- Taken branches perform an extra read; a page-crossing branch performs another.
- Indexed reads perform a correction cycle when their address crosses a page.
- Indexed stores always perform a dummy read before the write.
- A memory read-modify-write instruction reads the value, writes the old value,
  then writes the new value.
- Stack and control-flow instructions perform their documented dummy reads.
- Holding the hardware-ready signal inactive repeats read cycles, but never
  stalls a write cycle.

These details matter when an address selects a memory-mapped device. Do not use a
read-modify-write instruction on a device register unless that device explicitly
allows the read and both writes. Likewise, an indexed access can touch a
provisional address before reaching its final device address.

For deterministic loop timing, keep branch source and target in the same page,
and align indexed data so the maximum index cannot cross a page. Remember that
the final loop branch usually has a different duration because it is not taken.

```asm
; X iterations: 5 cycles per taken iteration, 4 on the final iteration.
loop:   dex            ; 2 cycles
        bne loop       ; 3 taken, 2 not taken; assumes same page
```

## Undocumented NMOS opcodes

Fanticon emulates all 256 opcode bytes, including undocumented NMOS operations.
They are useful for size or speed optimization but are less readable, may not be
accepted by every assembler, and are not portable to all 6502-family CPUs. Prefer
official instructions unless the benefit is measured and the code is explicitly
targeted at Fanticon's NMOS core.

Fanticon's assembler accepts the undocumented mnemonics and addressing modes
listed below, including the `ISB`, `SBX`, and `JAM` aliases. Where the NMOS has
duplicate opcode bytes for the same syntax, it emits a stable canonical
encoding: `0B` for `ANC #`, `02` for `KIL`/`JAM`, and `80`, `04`, `14`, `0C`, or
`1C` for addressed `NOP`. The normal `SBC #` spelling emits the official `E9`.
Emit `EB` or another particular alternate byte with `DFB` or `HEX` when required.

### Stable combined operations

| Mnemonic | Operation | Opcodes by mode |
| --- | --- | --- |
| `SLO` | `ASL M`, then `A ← A | M` | `(zp,X) 03`, `zp 07`, `abs 0F`, `(zp),Y 13`, `zp,X 17`, `abs,Y 1B`, `abs,X 1F` |
| `RLA` | `ROL M`, then `A ← A & M` | `23`, `27`, `2F`, `33`, `37`, `3B`, `3F` in the same mode order |
| `SRE` | `LSR M`, then `A ← A ^ M` | `43`, `47`, `4F`, `53`, `57`, `5B`, `5F` |
| `RRA` | `ROR M`, then `ADC M` | `63`, `67`, `6F`, `73`, `77`, `7B`, `7F` |
| `SAX` | `M ← A & X` | `(zp,X) 83`, `zp 87`, `abs 8F`, `zp,Y 97` |
| `LAX` | `A ← M; X ← M` | `(zp,X) A3`, `zp A7`, `abs AF`, `(zp),Y B3`, `zp,Y B7`, `abs,Y BF` |
| `DCP` | `DEC M`, then compare `A` with `M` | `C3`, `C7`, `CF`, `D3`, `D7`, `DB`, `DF` |
| `ISC`/`ISB` | `INC M`, then `SBC M` | `E3`, `E7`, `EF`, `F3`, `F7`, `FB`, `FF` |

For the seven-mode rows, cycle counts in the listed order are `8, 5, 6, 8, 6,
7, 7`. These are read-modify-write operations and perform the old-value write as
well as the final write.

### Immediate and special operations

| Mnemonic | Opcode | Cycles | Operation |
| --- | ---: | ---: | --- |
| `ANC #` | `0B`, `2B` | 2 | `A ← A & #`; set `C` equal to result bit 7 |
| `ALR #` | `4B` | 2 | `A ← A & #`, then logical shift right |
| `ARR #` | `6B` | 2 | `A ← A & #`, then rotate right; has special `C`/`V` and decimal behavior |
| `XAA #` | `8B` | 2 | `A ← (A | $EE) & X & #`; set `N Z` |
| `LAX #` | `AB` | 2 | `A ← X ← (A | $EE) & #`; set `N Z` |
| `AXS #`/`SBX #` | `CB` | 2 | `X ← (A & X) - #`; `C` reports no borrow |
| `SBC #` | `EB` | 2 | Alias of official immediate `SBC` |
| `LAS abs,Y` | `BB` | `4+P` | `A ← X ← SP ← M & SP` |
| `AHX (zp),Y` | `93` | 6 | Unstable high-byte-masked store |
| `AHX abs,Y` | `9F` | 5 | Unstable high-byte-masked store |
| `TAS abs,Y` | `9B` | 5 | `SP ← A & X`, then unstable masked store |
| `SHY abs,X` | `9C` | 5 | Store `Y` masked by an address-derived high byte |
| `SHX abs,Y` | `9E` | 5 | Store `X` masked by an address-derived high byte |

The unstable instructions reproduce the deterministic behavior used by
Fanticon's NMOS conformance model (including its `$EE` magic-mask value). Their
results can vary on physical chips with silicon revision, temperature, and bus
conditions. Use them only when Fanticon itself is the target.

For the unstable stores, let `H` be the unindexed base address's high byte plus
one, wrapping at 8 bits. `AHX` writes `A & X & H`; `TAS` first sets `SP=A & X`
and writes `SP & H`; `SHX` writes `X & H`; and `SHY` writes `Y & H`. If indexing
crosses a page, the written value also replaces the high byte of the destination
address. This address corruption is part of the emulated NMOS behavior, not an
assembler error.

### Undocumented NOP and JAM opcodes

Undocumented NOPs still fetch their operands and perform normal addressing-mode
bus reads; they are not all equivalent to `EA`.

| Form | Opcodes | Cycles |
| --- | --- | ---: |
| Implied | `1A 3A 5A 7A DA FA` | 2 |
| Immediate | `80 82 89 C2 E2` | 2 |
| Zero page | `04 44 64` | 3 |
| Zero page,X | `14 34 54 74 D4 F4` | 4 |

The JAM/KIL opcodes are `02 12 22 32 42 52 62 72 92 B2 D2 F2`. Executing one
halts useful instruction execution until reset. Do not use JAM as a normal wait
primitive unless the program is intentionally handing control back to a reset
mechanism.

## Efficient 6502 code

The fastest code often comes from arranging data around the processor rather
than searching for a clever instruction sequence.

- Put frequently accessed variables and pointers in zero page. A zero-page load
  is typically one byte shorter and one cycle faster than an absolute load.
- Use `X` or `Y` as loop counters so `DEX`/`DEY`/`INX`/`INY` avoid memory traffic.
- Choose `(zp),Y` for walking a buffer through a zero-page pointer. Choose
  `(zp,X)` for selecting among adjacent zero-page pointers.
- Align tables to pages when indexed read timing must be constant.
- Keep hot loops inside one page to avoid the taken-branch page penalty.
- Cache a reused memory value in `A`, `X`, or `Y` when register pressure permits.
- Use `BIT` to test memory without destroying `A`.
- Prefer a counted loop over unrolled code when code size and instruction-cache
  locality matter; unroll only after measuring the VM workload.
- Treat zero page and stack space as scarce shared resources and document their
  ownership in larger programs.

### Pointer traversal

```asm
; ptr is a two-byte zero-page pointer. Process 256 bytes starting at ptr.
        ldy #$00
loop:   lda (ptr),y
        ; process A
        iny
        bne loop
```

If the buffer crosses a page, some `LDA` operations take six rather than five
cycles. Align the buffer or account for that variation when timing is critical.

### Clearing a page

```asm
        lda #$00
        ldx #$00
loop:   sta $0200,x
        inx
        bne loop
```

The loop naturally executes 256 times because `X` wraps from `$FF` to `$00` and
sets `Z`.

## Portability and correctness checklist

Before treating a routine as complete:

- Confirm which registers, flags, zero-page bytes, and stack bytes it clobbers.
- Establish carry explicitly before every independent `ADC` or `SBC` chain.
- Ensure decimal mode has the expected state.
- Check every relative branch is in range and whether page crossing changes its
  timing.
- Check indexed tables for page-crossing timing in their full index range.
- Do not assume reset initializes `A`, `X`, or `Y`; initialize program state.
- Keep `SP` balanced across every control-flow path.
- End interrupt handlers with `RTI`, and normal subroutines with `RTS`.
- Avoid undocumented opcodes when code may be moved to a different 6502-family
  target.
- Avoid read-modify-write and unintended dummy reads on sensitive device
  registers.

## Emulator accuracy

Fanticon targets the standard NMOS MOS 6502, not the CMOS 65C02. The CPU core is
tested instruction-by-instruction against all 2.56 million cases in the
SingleStepTests 6502 suite, including register state, memory results, cycle count,
and ordered bus accesses for all 256 opcodes. Separate tests cover RESET, IRQ,
NMI, ready-line stalls, overflow-pin edges, interrupt polling, and JAM recovery.

That accuracy means code may deliberately use NMOS behavior described here, but
it also means accidental page crossings, dummy accesses, decimal quirks, and the
indirect-jump wrap behavior are visible exactly where real code would encounter
them.
